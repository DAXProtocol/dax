The Protocol Engine · 4-Stage Lifecycle

CREATE · ESCROW · EVIDENCE · RESOLVE

DAX replaces trusted middlemen with an automated, non-custodial EVM state machine running on Arbitrum One:

STAGE 01
CREATE
Bilateral or marketplace agreement initiated. Canonical terms and milestones are cryptographically bound via EIP-712 typed signatures (`termsHash`).
STAGE 02
ESCROW
Tokens (USDT, USDC, ARB, ETH) are locked directly in `DAX_Agreement.sol`. Zero admin keys, zero server custody. Funds release only on milestone satisfaction.
STAGE 03
EVIDENCE
Work deliverables, bills of lading, or receipts are fingerprinted client-side with SHA-256 and committed as immutable Merkle roots on-chain.
STAGE 04
RESOLVE
Disputed escrows automatically escalate to `DAX_Court.sol`. Staked community jurors vote using a commit-reveal Schelling-point game with slashing for corruption.

Flywheel & Unit Economics · Defensibility

The Network Effects of
Decentralized Arbitration

How DAX builds compounding network effects with decentralized dispute resolution:

💸
Competitive Protocol Fee

Configurable protocol fee (capped at 0.25%) deducted upon successful deliverable release. Highly competitive against centralized platforms (1.5%–3.5%) while generating sustainable protocol revenue.

⚖️
Anti-Bribery Schelling Game

Commit-reveal voting (`keccak256(vote + salt)`) prevents vote-buying. Jurors must stake collateral to participate. Dishonest voters are slashed; honest jurors earn dispute fees.

🌍
Non-Custodial Coordination

DAX operates purely as a non-custodial software coordination protocol. Users retain exclusive key custody, eliminating centralized counterparty liability and single points of failure.
